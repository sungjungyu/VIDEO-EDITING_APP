# 프론트엔드 (팀원1) 재설계 기획서

> 이 문서는 팀원1이 이미 구현한 `static/editor.html`(단일 파일, Tailwind CDN, Vanilla JS)을 기반으로,
> 화면 레이아웃을 캡컷(CapCut) 스타일로 재구성하고 AI 기능을 전면에 부각시키기 위한 재설계 기획서입니다.
> 기존 구현의 데이터 구조(`SEGMENTS`, API 연동 흐름)는 최대한 재사용하되, 레이아웃과 사용 시나리오는 새로 설계했습니다.
> 다른 팀원(팀원2 백엔드, 팀원3 AI 파이프라인, 팀원4 미디어 엔진) 담당 클로드가 연동점을 확인할 때 참고할 수 있도록 작성했습니다.

---

## 1. 기존 구현 대비 변경 배경

기존 구현은 "영상 1개 업로드 → 분석 → 하드코딩된 예제 타임라인" 구조였습니다. 재설계 목표는 다음 두 가지입니다.

1. **화면 레이아웃을 캡컷 스타일로 전환**하고, 이 프로젝트의 핵심 차별점인 **AI 기능 패널을 크게 부각**시킵니다.
2. **여러 영상을 하나의 타임라인에 배치하고 편집하는 실제 시나리오**를 지원하도록 데이터 구조와 하단 타임라인을 재설계합니다. 지금처럼 하드코딩된 단일 예제가 아니라, 좌측에서 업로드한 영상들을 실제로 하단 타임라인에 끌어다 배치하는 방식입니다.

## 2. 전체 화면 레이아웃

```
┌──────────────────────────────────────────────────────┐
│  TopBar: 로고 / [내보내기]                              │  56px
├───────┬────────────────────┬───────────────────────────┤
│ 좌측   │                    │                            │
│ 도구   │   중앙 미리보기 영역   │   우측 AI 패널               │
│ 패널   │   (비디오 플레이어 +  │   (AI 분석 시작/진행 상태 +   │
│ (탭)   │    재생 컨트롤만)     │    AI 수정요청 채팅)         │
│  30%   │       30%          │         40%               │
├───────┴────────────────────┴───────────────────────────┤
│  하단 타임라인 패널 (비디오 트랙 + 자막 트랙, 스냅 on/off)     │
└──────────────────────────────────────────────────────┘
```

가로 비율: **좌측 30% / 중앙 30% / 우측 AI 패널 40%**

### 2-1. 좌측 도구 패널

- 캡컷처럼 좁은 고정 폭(아이콘 + 라벨)으로 표시, 클릭 시 패널이 확장되는 방식
- 탭 구성:
  - **미디어 탭**: 업로드된 영상 클립 목록 표시. 클릭 시 업로드 전용 화면으로 이동(§4 참고)
  - **스타일 탭**: 스타일 프리셋 선택 (정석맛/매운맛/순한맛) — 기존 `select#style-select` 기능 이전

### 2-2. 중앙 미리보기 영역

- 기존 중앙 영역에 있던 다른 컨트롤(영상 선택 버튼, 스타일 선택, AI 분석 시작 버튼, 파일명/진행 상태)은 모두 좌측/우측으로 이동
- 순수하게 `<video>` 플레이어 + 재생/탐색 컨트롤만 남김

### 2-3. 우측 AI 패널 (확대, 40%)

```
┌─────────────────────────┐
│  [분석 시작] 버튼          │  ← 기존 중앙 영역에서 이동
│  진행 상태 (진행바+단계명)   │  ← 기존 중앙 영역에서 이동
├─────────────────────────┤
│  [컷편집 해줘] [자막생성 해줘] │  ← 신규: 빠른 명령 버튼
├─────────────────────────┤
│  AI 수정 요청 채팅          │  ← 기존 기능 그대로, 패널 확대로
│  (자연어 명령 입력 가능)      │     더 크고 잘 보이게
└─────────────────────────┘
```

- 빠른 명령 버튼(컷편집/자막생성)과 자연어 채팅 입력 두 가지 방식을 모두 지원합니다. 버튼은 채팅에 동일 문구를 자동 입력하고 전송하는 방식으로 구현하면 로직 중복 없이 처리 가능합니다.

### 2-4. 하단 타임라인 패널

§3에서 상세 설명합니다.

## 3. 하단 타임라인 설계

### 3-1. 트랙 구조

```
┌────────────────────────────────────────────────────────┐
│  눈금자 (시간 표시, 기존 renderRuler 로직 재사용)             │
├────────────────────────────────────────────────────────┤
│  [비디오 트랙]                                             │
│  ┌──────────┐┌────────────┐┌──────────┐                 │
│  │ 촬영본1   ││  촬영본2    ││ 촬영본3   │                  │
│  └──────────┘└────────────┘└──────────┘                 │
├────────────────────────────────────────────────────────┤
│  [자막 트랙] (별도 트랙, 분석/생성된 구간에만 표시)              │
│              ▭▭▭  ▭▭  ▭▭▭▭                              │
├────────────────────────────────────────────────────────┤
│  플레이헤드 (드래그 가능, 기존 로직 재사용)                     │
└────────────────────────────────────────────────────────┘
```

- **비디오 트랙과 자막 트랙을 분리**했습니다. 비디오 트랙 안에 자막까지 표시하면 클립이 여러 개 배치될 때 시각적으로 복잡해지기 때문입니다.

### 3-2. 클립(미디어 객체) 상태별 표시

| 상태 (`analysis_status`) | 타임라인 표시 |
|---|---|
| `pending` (분석 전) | 단색 회색 블록 + 파일명. 좌우 끝에 트림 핸들(드래그로 러프 컷) |
| `analyzing` (분석 중) | 회색 블록 + 로딩 스피너 |
| `analyzed` (분석 완료) | 세그먼트별 색상 블록(파랑=유지 `--keep`, 빨강=제거 `--cut`)으로 세분화. 기존 `toggleSegment` 클릭 토글 로직 재사용 |

### 3-3. 인터랙션

1. **드래그 앤 드롭**: 좌측 미디어 목록의 클립을 하단 비디오 트랙으로 끌어다 놓으면 배치됨
2. **스냅(자석) 기능 on/off**: 켜져 있으면 클립을 다른 클립 끝, 플레이헤드 위치 등에 자동으로 달라붙게 배치. 꺼져 있으면 자유롭게 배치. 하단 타임라인 상단에 토글 버튼으로 제공
3. **러프 컷 (분석 전)**: 클립 좌우 끝 트림 핸들을 드래그해 앞뒤 불필요한 구간을 대략적으로 잘라냄 → 이 결과가 `timeline_range`에 반영됨
4. **선택**: 클립 클릭(Shift+클릭으로 다중 선택) → 테두리 강조 표시
5. **분석 요청**: 선택된 클립에 한해 우측 AI 패널 [분석 시작] 클릭 → 선택된 클립들의 `timeline_range` 구간만 분석 API로 전송 (§5 참고)
6. **AI 명령 실행**: 우측 AI 패널의 [컷편집 해줘]/[자막생성 해줘] 버튼 또는 채팅 명령 → 분석 완료된 클립들에 대해 세그먼트 단위로 제안 적용

## 4. 업로드 전용 화면 (좌측 미디어 탭 진입 시)

```
┌───────────────────────────┬───────────────────────────┐
│  좌측: 영상 업로드            │  우측: 프로젝트 설정          │
│  - 여러 영상 파일 업로드       │  - 영상 순서 배치(드래그로     │
│    (multiple)               │    정렬)                    │
│  - 업로드된 파일 목록 표시     │  - 스토리라인/설명 텍스트 입력  │
│                             │    (같은 주제로 묶는 컨텍스트)  │
│                             │  - [메인 화면으로] 버튼        │
└───────────────────────────┴───────────────────────────┘
```

- 이 화면에서는 **분석을 실행하지 않습니다.** 업로드와 순서/설명 입력까지만 처리하고, 실제 분석은 메인 화면의 타임라인에서 러프 컷을 마친 뒤 선택적으로 실행합니다(§5 참고).
- "같은 주제로 여러 영상을 찍었을 때 하나로 묶기" 요구사항을 반영해, 순서 배치와 스토리라인 설명 입력을 이 화면에서 처리합니다. 스토리라인 설명은 이후 AI 컷편집/자막생성 명령 시 맥락 정보로 함께 전달됩니다.

## 5. 분석 시점 결정: 타임라인 배치 후 선택적 분석

### 5-1. 검토한 대안과 결정

| 대안 | 설명 | 채택 여부 |
|---|---|---|
| 업로드 시점 즉시 분석 | 업로드하자마자 전체 영상을 분석 | 미채택 |
| 업로드 화면에서 선택적 분석 | 업로드 화면에서 체크박스로 분석 대상 선택 후 즉시 분석 | 미채택 |
| **타임라인 배치 후 선택적 분석** | 타임라인에 배치 → 러프 컷으로 불필요한 구간 제거 → 남은 구간만 선택해서 분석 | **채택** |

### 5-2. 근거

Gemini 영상분석 API는 영상 길이에 비례해 토큰이 소모됩니다(1초당 약 300토큰). "같은 주제로 여러 번 촬영"하는 상황 자체가 애초에 일부는 버려질 영상이 섞여 있다는 뜻이므로:

1. 업로드 시점에 미리 분석하면 결국 쓰지 않을 영상까지 분석 비용이 들어갑니다.
2. **타임라인에 실제로 배치하고, 사용자가 트림 핸들로 러프 컷까지 마친 뒤** — 즉 "이 구간을 진짜 쓸 거다"라고 확정한 뒤에만 분석을 실행하면 토큰 낭비를 최소화할 수 있습니다.
3. 러프 컷은 AI 도움 없이 사용자가 직접 대략적인 트리밍만 하는 것이라 부담이 적고, 이 과정만으로도 분석 대상 길이가 줄어들어 비용이 절감됩니다.

### 5-3. 참고: Gemini 영상분석 비용 추정 (2026년 7월 기준)

- Gemini는 영상 파일을 File API로 업로드하면 내부적으로 초당 1프레임(1 FPS)씩 자동 샘플링하여 음성+시각 정보를 함께 분석합니다. 별도의 프레임 추출 파이프라인을 직접 구축할 필요가 없습니다.
- 토큰 소모량: 프레임당 258토큰(1 FPS 기준) + 오디오 초당 32토큰 ≈ **영상 1초당 약 300토큰(입력 기준)**
- 비용 예시(입력 토큰 기준, 5분 영상 1개):
  - Gemini 2.5 Flash-Lite ($0.10/백만 토큰): 약 $0.009 (약 12~13원)
  - Gemini 2.5 Flash ($0.30/백만 토큰): 약 $0.027 (약 37~38원)
- 캡스톤 시연 규모에서는 총비용이 무시할 만한 수준이나, 실사용자 확대 시에는 재계산이 필요합니다.
- 이 가격은 2026년 7월 기준이며, Google이 모델 라인업과 가격을 자주 개편하고 있어 실제 구현 시점에 재확인이 필요합니다.

### 5-4. Whisper와의 역할 분담 (팀원3과 협의 필요)

Gemini 영상분석이 음성 트랙도 함께 처리할 수 있지만, 자체 음성 인식의 타임스탬프 정밀도는 Whisper(STT 전용 모델)보다 낮을 가능성이 있습니다. 카라오케 자막 하이라이트에는 단어 단위의 정밀한 타임스탬프가 필요하므로:

- **Gemini 영상분석**: 시각 정보 기반 컷 후보 판단, 장면 요약, 맥락 이해
- **Whisper**: 자막용 정밀 단어 단위 타임스탬프 추출

이 역할 분담을 유지할지, Gemini 하나로 통일할지는 팀원3과 별도 협의가 필요합니다.

## 6. 데이터 구조

### 6-1. 미디어 객체 (좌측 목록 및 타임라인 클립)

```js
{
  media_id: "media_001",
  filename: "촬영본1.mp4",
  file_path: "uploads/media_001.mp4",
  duration: 180.0,

  // 타임라인 배치 정보 (드래그 배치 + 러프 컷 반영)
  timeline_position: 0,           // 타임라인 내 배치 순서/시작 지점
  timeline_range: { start: 12.0, end: 95.0 },  // 러프 컷으로 좁혀진 실제 사용 구간

  // 분석 상태
  analysis_status: "pending" | "analyzing" | "analyzed",

  // 분석 완료 후 채워지는 메타데이터
  metadata: {
    segments: [
      { start: 12.0, end: 15.3, text: "...", visual_desc: "...", suggested_cut: false }
    ],
    transcript_words: [ { word: "...", start: 12.0, end: 12.4 } ],  // 카라오케 자막용 (Whisper 결과)
    scene_summary: "..."   // Gemini 영상분석 결과 요약
  }
}
```

- `metadata`는 AI가 컷편집/자막생성 명령을 수행할 때 참고하는 정보입니다. AI는 타임라인에 배치된 미디어 객체들을 순회하며 각 객체의 `metadata.segments`를 참고해 컷 후보를 판단하고, 사용자 승인 후 팀원4에 전달할 최종 `cuts` 배열(§7 참고)로 변환됩니다.
- 프로젝트(스토리라인 설명, 여러 미디어 객체의 순서)는 별도의 상위 객체로 관리합니다:

```js
{
  project_id: "proj_001",
  storyline_description: "샤이니 5인 활동 컨셉 매쉬업...",  // 업로드 화면에서 입력
  media_list: [ /* 미디어 객체 배열, timeline_position 순서대로 */ ]
}
```

## 7. 팀원4(미디어 엔진)와의 연동점

- 최종 렌더링 요청 시 전달하는 `cuts` 스키마(팀원4 기획서 §4-3에서 확정)는 **여러 미디어 객체의 `timeline_range` + 세그먼트 토글 결과를 하나의 시간축으로 통합**해서 만들어야 합니다. 즉 프론트엔드가 여러 클립을 하나의 최종 `cuts` 배열로 변환하는 로직이 필요합니다.
- 카라오케 자막에 필요한 `words`(단어 단위 타임스탬프)는 미디어 객체의 `metadata.transcript_words`에서 가져와 `/render` 요청의 `subtitles[].words`로 매핑합니다.

## 8. 팀원2(백엔드)와의 연동점

- 업로드 화면에서의 다중 파일 업로드는 `/upload`를 여러 번 호출하거나, 다중 파일을 한 번에 받는 엔드포인트가 필요한지 백엔드와 협의가 필요합니다(현재 백엔드 기획서는 단일 파일 업로드 기준으로 작성됨).
- "선택적 분석"을 지원하려면 `/edit`(또는 신규 분석 엔드포인트)이 **미디어 객체 단위로 개별 호출 가능**해야 합니다. 기존 백엔드 기획서의 `/edit`은 `job_id` 하나에 대해 전체 분석을 실행하는 구조라, 이를 미디어 객체(클립) 단위로 세분화할지 협의가 필요합니다.

## 9. 팀원3(AI 파이프라인)과의 연동점

- Gemini 영상분석 API로의 전환(§5-3)에 따라, 팀원3의 분석 파이프라인이 "텍스트만 처리"에서 "영상 파일 자체를 업로드해서 처리"하는 방식으로 바뀌어야 합니다.
- §5-4에서 언급한 Whisper와 Gemini의 역할 분담을 팀원3과 확정해야 합니다.
- 스토리라인 설명(`storyline_description`)을 AI 컷편집/자막생성 명령 시 프롬프트에 맥락으로 포함해야 하므로, 팀원3의 프롬프트 설계에 이 필드가 반영되어야 합니다.
