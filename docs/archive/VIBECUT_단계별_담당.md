## 0. 기초 보수 (확장 전에 먼저, 1~3일 규모)

새 기능을 붙이기 전에 기존 VIBE CUT의 고장 난 곳과 안 쓰는 부분을 정리한다.

### 렌더 버그 4건 (성준규)

| # | 문제 | 위치 | 내용 | 조치 |
| --- | --- | --- | --- | --- |
| 1 | 없는 함수 호출 | `app.py:96` | `verify_gemini_connection()`이 존재하지 않음. 매번 오류가 나지만 예외 처리로 묻힘 | 확인 함수 구현 또는 호출 제거 |
| 2 | 미리보기 ≠ 렌더 | `main.py` 자막 생성 | 외곽선·배경 박스를 꺼도 렌더 결과는 항상 켜진 상태 | 옵션 값을 백엔드까지 전달해 반영 |
| 3 | 자막 스타일 하드코딩 | `index.html:1561` | 렌더 요청 시 색 흰색, 크기 36으로 강제 덮어씀 | 덮어쓰기 제거, 설정값 전달 |
| 4 | 컷 후 자막 시각 (의심) | 렌더 단계 | 중간 구간 삭제 후 자막 시각이 밀릴 위험 | 실제 테스트로 확인 → 밀리면 재계산 |

### 껍데기 UI 숨기기 (신정빈)

눌러도 기능이 없는 화면 요소. 이번 계획에서 구현하지 않으면 숨긴다.

- 카라오케 효과, 페이드 인/아웃 토글
- 템플릿, 요소·필터 버튼
- 오디오 탭, 텍스트 탭 ("준비 중")
- 객체 패널 탭 (배경, 스마트, 오디오, 애니메이션, 속도)
- 실행취소·다시실행 버튼

### 데드코드 삭제 (신정빈)

- `static/editor.html`, `static/app.js`, `static/app.css` (구버전, 미사용)
- `main.py`의 `_build_dummy_commands()` (호출 없음)

## 1단계 진행 순서

1단계는 데이터가 흐르는 순서대로 앞 칸이 뒤 칸을 막는다.

```
1-1 입력 → 1-2 전처리 → 1-3 구조화 → 1-4 화면 → 1-5 선택 → 1-6 자동 압축
```

그래서 **처음부터 끝까지 얇게 한 줄 먼저 뚫고**, 그다음 각 칸을 두껍게 만든다.

### 1차: 얇게 한 줄 뚫기

목표: 원본 1개 → 트리가 화면에 뜨기

| 담당 | 할 일 | 완료 기준 |
| --- | --- | --- |
| 공통 | 테스트 원본 촬영 (여러 클립, 총 30분~1시간, NG 반복·지시어 일부러 포함) | 원본 확보 |
| 공통 | 원본 1개를 평소처럼 직접 편집하며 러프컷·자막·꾸미기 시간 기록 | 평가 기준선 확보 |
| 조경우 | 4단 트리 **JSON 스키마** 초안 → 팀 합의 | 스키마 확정 |
| 조경우 | Gemini 영상 이해 비교 (Flash-Lite vs Flash, 저해상도 vs 고해상도) | 모델·해상도 결정 |
| 권용관 | 받아쓰기 비교 (Gemini Transcribe vs Whisper API) 후 교체, **단어 타임스탬프** 출력 | 문장 + 단어 시각 JSON |
| 권용관 | 여러 클립 업로드, 촬영 시각 정렬, 압축·업로드 병렬 처리 | 클립 여러 개가 한 작업으로 처리 |
| 신정빈 | 스키마 기준 **가짜 데이터로** 트리 화면 먼저 구현 | 가짜 JSON으로 트리 표시 |
| 성준규 | 0단계 렌더 버그 4건 | 미리보기 = 렌더 |

> 신정빈은 스키마만 정해지면 AI 결과를 기다리지 않고 가짜 데이터로 화면을 먼저 만들 수 있다. 4명이 동시에 움직이는 핵심.

### 2차: 연결하고 두껍게

목표: 실제 원본 → 트리 → 선택 → 목표 분량

| 담당 | 할 일 |
| --- | --- |
| 조경우 | 받아쓰기 + 장면 목록을 합쳐 4단 트리 생성 (1-3), LLM 출력 시각 검증 로직 |
| 권용관 | 1시간 단위 조각 분할·겹침·병합, 선택 모드 API (1-5) |
| 신정빈 | 실제 트리 연결, 체크박스 선택, **실시간 총 길이 / 목표 분량** 표시 |
| 성준규 | 단어 경계 컷 + 오디오 페이드 (선택 결과 바로 미리보기 재생) |

### 3차: 자동 압축 (1-6)

| 담당 | 할 일 |
| --- | --- |
| 조경우 | 하이라이트 점수 → 시작·끝 → 군더더기 → 내부 압축 → 분량 맞춤 |
| 신정빈 | 노드 잠금(꼭 넣기) UI, AI 제안 결과를 체크 상태로 표시 |
| 권용관 | 잠금 노드 + 남은 시간 예산을 압축 요청으로 넘기는 API |
| 성준규 | 3단계 편집 지시서 → FFmpeg 렌더 준비 시작 |

## 지금 당장 첫 액션

1. **조경우:** 4단 트리 JSON 스키마 초안 작성 (전체 작업의 출발점)
2. **전원:** 테스트 원본 촬영 + 수동 편집 시간 기록
3. **권용관·조경우:** 받아쓰기, 영상 이해 비교 실험 착수
4. **신정빈·성준규:** 스키마 나오기 전까지 UI 정리와 렌더 버그 수정

- [ ] 영상 이해 모델·해상도 확정

- [ ] 4단 트리 JSON 스키마 합의
- [ ] 기준선 데이터(수동 편집 시간) 확보

## 주의

조경우·권용관의 실험 결과가 나머지 두 명의 다음 작업을 막는다. 트리 UI는 스키마가, 단어 경계 컷은 단어 타임스탬프가 있어야 가능하다. 두 실험은 **이번 주 안에 1차 결과**를 목표로 한다.
