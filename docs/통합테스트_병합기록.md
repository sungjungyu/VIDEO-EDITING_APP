- 앱 분석의 Step 2를 로컬 Whisper → **Gemini 받아쓰기**(`transcriber.py`, `gemini-3.5-transcribe`)로 바꿨다.
  정리(`clean_segments`)·무음 기준 단어 경계 보정까지 거치고, 세그먼트에 `words`(단어 시각)가 들어간다.

- 무료 한도 아끼기: 분석·수정 요청마다 보내던 `verify_gemini_connection()` 요청 제거,
  Gemini 사용 한도 초과(429) 시 `gemini-3.5-flash-lite`로 넘김 (main.py, scene_selector.py — 한도는 모델마다 따로).
- 받아쓰기 한도 초과 시 안내 문구: "Gemini 받아쓰기 사용 한도를 다 썼습니다. 무료 키는 하루 25회…"

## 영상분석 연결 + 실제 장면 트리 (10/11)

- 분석 때 조경우 scene_analyzer(`make_lowres`, `analyze_clip`, `clean_scenes`, 파일은 수정 안 함)로 장면 목록을 만든다.
  받아쓰기와 **동시에** 실행하고, 결과(장소·활동·사건·요약)를 컷 판단(step3)의 영상 문맥에도 넣는다.
- `scene_tree.py`: 장면 + 대사 → 임시 4단 트리 (장소 → 일 → 상황 → 대사).
  같은 장소 재방문은 새 노드, 대사는 가운데 시각이 속한 장면에 넣고 장면 범위로 자름 (부모가 자식을 항상 포함).
  영상분석이 실패하면 분석은 계속하고 대사 사이 쉼으로 나눈 단순 트리로 대체 (`scene_error`로 화면에 표시).
- 분석 결과에 `scenes`, `scene_tree`, `scene_error` 추가 → 편집 설정 화면이 가짜 트리 대신 실제 트리를 쓴다.
  목표 분량 기본값은 영상 길이의 절반. 상태 문구로 실제 트리인지 예시 트리인지 표시.
- 설정: `SCENE_MODEL`(기본 gemini-3.5-flash-lite), `SCENE_MIN_SEC`(기본 10초, 이보다 짧은 장면은 합침)
- 테스트: `tests/test_scene_tree.py` (7개, prompt_builder `normalize_tree`·`calc_duration` 호환 포함),
  브라우저로 분석 → 편집 설정(4개 탭 실제 내용) → AI 가편집 → 렌더 확인

## 4단 트리 구현 (10/12) — 위 임시 트리를 대체

정의: L1 장소×세션 → L2 행동 흐름(화면에서 보이는 것만) → L3 세부 행동 → L4 장면(3~7초, 대사가 붙음).
자세한 규칙·실측은 `scene_tree_실행가이드.md`.

- `shot_analyzer.py` (새 파일): L4 장면 분석. scene_analyzer와 같은 방식(저해상도·무음 영상 → Gemini)이지만 3~7초 단위로,
  장면마다 화면 설명·장소·행동·인물·**화면 글자**(간판·메뉴판, 보정 근거)를 뽑는다. 긴 클립은 5분 조각으로.
  scene_analyzer.py는 수정하지 않았다 (ffmpeg 실행·시각 변환 함수만 가져다 씀). 앱은 이제 scene_analyzer의 `analyze_clip`을 부르지 않는다.
- `scene_tree.py` (다시 씀): 정형화 → 합치기(장면 경계를 문장 사이로, 3~7초로 나누기, 대사 붙이기) → AI 보정 + 구조화(1회) → 트리.
  AI는 시각을 만들지 않고 L3 시작 장면 id만 고른다. 보정은 발음(자모) 유사도로 검사해서 받는다. AI가 실패하면 규칙으로 트리를 만든다.
- `app.py` 분석 흐름: 받아쓰기 ∥ 장면 분석 → 4단 트리(대사 보정 포함) → 컷 판단(step3, 보정된 대사 + 세부 행동 요약을 영상 문맥으로).
  예전 `step2_refine_transcript`(대사만 보는 표기 교정)는 앱에서 부르지 않는다 (보정이 대신함, backend/는 그대로).
  분석 결과에 `scene_tree_meta`(source·장면 수·보정 내역) 추가.
- `static/index.html` 편집 설정: 탭 이름(장소·세션 / 행동 흐름 / 세부 행동 / 장면), L1~L3 요약과 L4 대사 표시,
  AI가 고친 대사는 색을 바꾸고 원문을 툴팁으로. 예시 트리를 같은 4단 모양(카페·한강)으로 바꿈.
  정규화가 `summary`·`tags`를 남기게 해서 AI 가편집 지시문에도 장면 요약이 실린다 (예전에는 버려졌음).
- 설정 바뀜: `SCENE_MODEL`·`SCENE_MIN_SEC` 대신 `SHOT_MODEL`·`SHOT_CHUNK_SEC`·`SHOT_RESOLUTION`·`TREE_MODEL`
- 테스트: `tests/test_scene_tree.py` 32개(다시 씀), `tests/test_shot_analyzer.py` 9개 (API 없이 실행)
- 확인: 1분 47초 테스트 영상으로 명령줄·앱 분석 흐름을 실제 API로 실행 → L4 22개(모두 4~7초), 세션 1 / 흐름 2 / 세부 행동 7,
  대사 보정 1~2건, 경고 0건. Edge(Playwright)로 편집 설정 4개 탭에 실제 트리가 뜨고 체크·길이 계산이 되는 것 확인

## 알려진 한계 (이 브랜치에서)

- 자막 글자 크기: 미리보기는 화면 픽셀(px), 렌더는 영상 높이 288 기준 비율이라 크기가 정확히 같지는 않다 (비슷한 비율). 줄바꿈 글자 수(`max_chars_per_line`)는 렌더에 아직 반영 안 됨.
- AI 분석 step3에서 Gemini가 문장을 나누며 시각을 새로 만들어 낼 수 있다 (Whisper 시각이 아님). 받아쓰기 모듈의 단어 시각을 연결하면 해결 가능.
- **성준규 refactor의 "미사용 UI 숨김"이 신정빈 화면에는 적용되지 않았다.** 신정빈 화면은 refactor 이전 화면을 바탕으로 만들어졌다.
  → 정식으로 main에 합치려면 신정빈 화면을 최신 main 위에서 다시 맞추는 작업이 필요하다 (신정빈·성준규).
- **트리에서 말 없는 장면을 체크해도 렌더에 안 들어간다.** 체크 결과는 받아쓰기 문장(segments)의 cut으로만 반영되고,
  렌더는 문장 구간만 이어 붙인다. 체크한 트리 구간을 렌더에 그대로 넘기는 작업이 필요하다 (성준규·신정빈과 상의).
