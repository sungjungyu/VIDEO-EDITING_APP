# VIBE CUT v4 설계안 — 결과물 완성도와 자체 기술

> 작성: 2026-11-08 · 상태: **설계 (구현 전)** · 마감: 2026년 12월 초 (캡스톤디자인)
> 방향: **AI 모델을 학습하지 않고, 직접 설계한 규칙·알고리즘으로 푼다.** (학습 모델은 부록 A — 여유 시 선택)

### 구현 현황 (feature/v4)

| 항목 | 상태 | 코드 |
| --- | --- | --- |
| T1 평가 벤치마크 | ✅ 구현 (정답 검수는 아직) | `vibecut bench`, ④ 「평가용 정답」, `eval/bench.py` |
| T2 하이브리드 컷 판단 | ✅ 구현 (기본값은 지금 방식, bench 결과 후 결정) | `analysis/judge.py` `judge_hybrid`, `VIBECUT_JUDGE_MODE` |

| T5 오디오·연출 후처리 | ⬜ | |

## 1. 목표

1. **결과 영상의 완성도**를 높인다 — "AI가 자른 티"가 나지 않는 브이로그.
2. **직접 만든 기술**을 중심에 둔다 — "API만 가져다 쓴 것 아니냐"는 질문에 숫자로 답한다.
3. **팀원 누구의 노트북(Windows·Mac)에서나** GPU 없이 돌아간다.

핵심 전략

- 판단과 계산은 **직접 설계한 규칙·알고리즘**이 한다. Gemini 없이도 전체가 동작한다.
- Gemini는 **규칙이 애매하다고 판단한 곳에만** 묻는 보조 역할 + 장소 이름 같은 설명 글.
- 모든 기여는 **기준선 대비 수치·ablation·블라인드 평가**로 증명한다.

### 왜 학습이 아니라 프로그래밍인가

| 기준 | 규칙·알고리즘 | AI 학습 |
| --- | --- | --- |
| 데이터 | 시험용 원본 1시간이면 충분 | 학습용 데이터가 더 필요 — 지금 가장 부족한 것 |
| 일정 (약 3.5주) | 예측 가능 | 데이터 준비·학습·검증·배포로 1~2주 추가 |
| 결과물 완성도 | 컷 판단은 규칙 + Gemini, 체감 품질은 T3~T5 알고리즘에서 나옴 | 데이터가 적으면 규칙보다 크게 낫기 어려움 |
| 오류 추적 | 원인을 코드에서 바로 찾음 | 왜 틀렸는지 설명하기 어려움 |

컷 판단의 대부분(NG·군더더기·촬영 지시)은 규칙으로 잘 표현되고, 규칙으로 잡기 어려운 문맥 판단은 Gemini가 맡는다.
캡스톤에서 보이는 것은 "AI를 학습했는가"가 아니라 **"문제를 직접 풀고 증명했는가"** 다.

## 2. 현황 진단

### 2.1 이미 잘 되어 있는 것 (유지)

| 영역 | 자체 기술 |
| --- | --- |
| 받아쓰기 후처리 | 환각 필터, 무음 기준 단어 경계 보정, 문장 재분할 |
| 편집 계획 | 단어 안에서 자르지 않는 경계, 쉼 압축, 프레임 단위 정렬 (컷이 많아도 싱크 유지) |
| 렌더 | 필터 그래프 한 번에 인코딩, 결과 길이 오차 수 ms |
| 자막 | 미리보기 = 렌더 (같은 크기 규칙·줄바꿈 규칙을 양쪽에서 테스트) |
| LLM 사용 원칙 | 시각은 LLM에게 돌려받지 않음, 출력 검증, 실패 시 규칙으로 대체 |

### 2.2 결과물 품질이 새는 곳

| 빈 곳 | 지금 코드 | 결과물 증상 |
| --- | --- | --- |
| 품질을 재는 기준 | 지표가 압축률·단어 잘림·길이 오차 등 **기계적 정확도뿐** | 고쳐도 좋아졌는지 모름 |
| 컷 판단 확신도 | 규칙마다 **고정값**(지시어 0.8, NG 0.7, 일반 0.5), Gemini에는 **모든 문장**을 보냄 | 애매한 곳과 확실한 곳을 구분하지 못함, API 사용량 큼 |
| 구성 | 장면 점수 높은 순으로 채움, 흐름(시작·본론·마무리) 없음 | 정보는 있는데 재미가 없음 |
| 말 없는 장면(B롤) | 고른 장면은 통째로 들어감, 4초 넘는 쉼은 줄이지 않음 | 흔들리고 늘어지는 풍경 컷 |
| 점프컷 | 같은 클립에서 문장을 빼면 화면이 툭 튐 (줌은 강조 문장에만) | 컷이 많을수록 어색함 |
| 결과 비율 | 기본값이 항상 16:9 (영상 방향을 보지 않음) | 세로로 찍은 영상의 위아래가 대부분 잘림 |
| 소리 | 배경음악·잡음 제거 없음 | 아마추어 느낌 |

### 2.3 4단 트리 (장소 → 일 → 상황 → 대사)를 걷어내는 이유

- 트리는 장면 목록과 문장 목록을 시간으로 묶은 **사본**이라 새 정보가 없다.
- Gemini 장면 정리(`clean_scenes`)가 장소·활동이 같은 연속 장면을 이미 합치므로 **'상황' = '일'** 이 되어 단계가 겹친다.
- 계층 때문에 생긴 버그 2개:
  1. 화면(`web/js/panels/setup.js`): 부모가 체크된 상태에서 자식 체크를 풀어도 서버에는 부모가 그대로 가고, 다시 그릴 때 자식이 다시 체크된다 → 일·상황·대사 탭에서 빼기가 안 됨.
  2. AI 가편집(`editing/select.py`의 `fit_duration`): 장소·일을 📌 고정하면 그 안의 상황 노드를 한 번 더 세어 결과가 목표보다 크게 짧아진다 (목표 60초 → 30초 실측).
- 대체: **비트(평평한 목록)** — 3장 T3.

## 3. 기술 기여

| # | 기여 | 종류 | 우선순위 |
| --- | --- | --- | --- |
| T1 | 평가 벤치마크 (시험 데이터 + `vibecut bench`) | 데이터·실험 설계 | 필수 |
| T2 | 하이브리드 컷 판단 (확신도 계산 + 애매한 문장만 Gemini) | 알고리즘 | 필수 |
| T3 | 비트 분할 + 분량 제약 최적화 (동적계획법) | 알고리즘 | 필수 |
| T4 | 영상 품질 분석 → B롤 구간 | 영상처리 | 필수 |
| T5 | 오디오·연출 후처리 | 신호처리 | 필수 (작고 체감 큼) |

### T1. 평가 벤치마크

모든 기여를 숫자로 증명하는 토대. **AI 학습을 하지 않아도 시험 데이터는 필요하다.**

**시험 데이터**

- 편집 전 원본 영상 여러 개, **말이 있는 영상 합계 30분~1시간** (최소치 — 많을수록 결과를 믿을 수 있다).
- 문장마다 사람이 남김/자름(+이유)을 표시 (1시간이면 약 600~900문장, Gemini 1차 라벨을 고치는 방식으로 2~3시간).
  정답은 **반드시 사람이 정한다** — Gemini가 정하면 "AI끼리 채점"이 된다.
- 일부 영상은 사람이 편집한 정답 구간도 만든다 (T3 평가용).
- 규칙의 기준값을 조정할 때는 **영상(가능하면 사람) 단위로 조정용/시험용을 나눈다** — 같은 영상이 양쪽에 섞이면 점수가 부풀려진다.

**지표** (`vibecut bench` 명령 하나로 모든 표를 만든다)

| 지표 | 뜻 |
| --- | --- |
| 컷 판단 F1 (이유별) | 사람 라벨과 남김/자름 일치 |
| Gemini 호출 문장 비율 | 하이브리드가 Gemini에 보낸 문장 / 전체 |
| 구간 겹침 (IoU) | 고른 구간 vs 사람 정답 구간 |
| 분량 오차 | 결과 길이 / 목표 |
| B롤 평균 길이, 점프컷 수 | 연출 품질 대리 지표 |
| 블라인드 평가 | 두 버전을 섞어 보여 주고 5점 척도 |

### T2. 하이브리드 컷 판단

분류: 문장 하나 → **남김 / NG / 반복 / 군더더기 / 지시어**

**1) 확신도를 실제 근거로 계산** — 고정값 대신 "기준선에서 얼마나 떨어져 있는가"

| 규칙 | 확신 높음 | 애매함 |
| --- | --- | --- |
| NG (다시 말하기) | 다음 문장과 글자 겹침 95% | 겹침 62% (기준 60% 근처) |
| 군더더기 | "음… 어…"만 있음 | 추임새 반, 내용 반 |
| 지시어 | "다시 갈게"가 단독으로 나옴 | 문장 중간에 "다시"가 섞임 |
| 남김 | 길고 완결된 문장 | 짧고 끝이 흐린 문장, 앞뒤 쉼이 김 |

규칙 신호 보강 (모두 이미 있는 데이터로 계산):

- 글: 길이, 군더더기 비율, 촬영 지시 패턴, 문장 완결 여부(어미)
- 맥락: 다음 1~3문장과 글자 겹침(`bigram_overlap`), 앞 문장과 중복, 영상 내 위치
- 소리: 앞뒤 쉼, 말 속도(초당 글자), 받아쓰기 확신도(단어 확률)

**2) 애매한 문장만 Gemini에 묻는다** — 앞뒤 문장을 함께 보내 문맥을 준다. 확실한 문장은 규칙대로.

**3) Gemini가 없거나 실패하면 규칙 결과를 그대로** 쓴다 (지금 구조 유지).

- 기준값(애매함의 범위 등)은 T1의 조정용 영상으로 맞춘다 — 숫자 몇 개를 맞추는 것이지 AI 학습이 아니다.
- ablation: 규칙 신호를 글만 → +맥락 → +소리 순서로 더하며 F1 변화.
- 비교: **규칙 / Gemini 단독 / 하이브리드** — F1, Gemini 호출 비율, 처리 시간, API 비용.
- 기대: 하이브리드가 Gemini 단독과 비슷하거나 좋은 F1을 **훨씬 적은 호출**로 낸다 (실험으로 확인).

### T3. 비트 분할 + 분량 제약 최적화 (4단 트리 대체)

**비트** = 편집 단위의 평평한 목록.

- 말 비트: 남길 문장들을 주제 경계로 묶음. 경계 = 문장 간 어휘 응집도(TextTiling 방식) + 쉼 길이 + 화면 전환 신호.
- B롤 비트: 말 없는 구간에서 품질 곡선(T4)으로 찾은 최고 2~5초.
- id는 문장 id 기반 → 다시 분석해도 최대한 유지.

**선택 = 최적화 문제**:

```
최대화  Σ 비트 점수 − 중복 패널티
제약    결과 길이 ∈ 목표 ±5%
        시간 순서 유지 (예외: 훅 1개를 맨 앞에 미리 보여 주기, 켜고 끌 수 있음)
        B롤 비율, 최소·최대 조각 길이
풀이    동적계획법 (0.1초 단위 배낭 문제) → 최적해
```

- 비트 점수: 자체 규칙 점수(말 비중·강조·요청 단어 일치·화면 품질) + Gemini 점수는 있으면 더함 (없어도 동작).
- 평가: 지금 greedy vs DP — 목적함수 값, 분량 오차, 사람 정답과 구간 겹침.
- 화면 ③단계: 탭 없는 비트 목록 (체크 · 📌 · 이유 · 길이). 장소는 목록 안 구분선으로만 표시.
- 장소 이름 자막: 앞 비트와 장소가 달라지는 지점 (트리 불필요).

### T4. 영상 품질 분석 → B롤 구간

- **품질 곡선** (초당 2장, 128px 흑백, numpy만): 선명도(라플라시안 분산, 클립 중앙값 대비), 노출(밝기),
  흔들림(위상 상관으로 구한 화면 이동량의 '가속도' — 천천히 패닝은 괜찮고 손떨림만 낮게).
  → B롤에서 슬라이딩 윈도로 가장 좋은 2~5초 선택, 흔들리거나 어두운 구간 제외.
- ~~9:16 리프레이밍~~ **제외 (2026-11-08)**: 가로 영상은 가로로, 세로 영상은 세로로 편집하므로 가로 영상을 세로로
  바꿀 일이 거의 없다 (쇼츠 만들기도 범위 밖). 대신 **결과 비율을 영상 방향에 맞춰 자동으로** 정한다 —
  예전에는 기본값이 항상 16:9라 세로로 찍은 영상의 위아래가 대부분 잘렸다.
  쓰는 길이로 따져 세로 영상이 많으면 9:16, 비율 버튼을 직접 누르면 그 뒤로는 바꾸지 않고, 방향이 섞이면 경고.
- B롤 테스트에는 무료 스톡 영상(Pexels 등)도 쓸 수 있다 (흔들림 테스트는 휴대폰 원본으로).

### T5. 오디오·연출 후처리

| 항목 | 방법 |
| --- | --- |
| 점프컷 가리기 | 같은 클립 안의 컷마다 줌 1.0 ↔ 1.1 번갈아 (기존 `Effect` 재사용) |
| 배경음악 자동 줄이기 | 받아쓰기로 아는 말 구간으로 음량 곡선을 직접 계산 → 말 시작 **전에** 미리 줄임 (ffmpeg 압축기보다 정확) |
| 배경음악 선택 | 장면 분위기(`mood`)에 맞는 곡 자동 선택 + 사용자 음악 올리기 |
| 목소리 다듬기 | highpass + 약한 잡음 제거, 기존 loudnorm 유지 |
| 장소 전환 | 장소가 바뀌는 곳만 짧은 오디오 크로스페이드 + 장소 이름 자막 |

| 개수·길이 | 여러 개 합쳐서 말이 있는 영상 30분~1시간. 길이 제한 없음 (10초 미만은 문장이 적음) |
| 다양성 | 여러 사람·장소·종류(여행·음식·일상·설명). 한 사람이 절반을 넘지 않게 |
| 화질 | **상관없음** — 흐리고 흔들리는 영상이 오히려 좋은 시험 재료 |
| 소리 | **중요** — 말소리가 잘 들려야 함. 음악이 말보다 크거나, 너무 멀거나, 여럿이 동시에 떠드는 영상은 제외 |
| 형식 | mp4·mov·m4v·avi·mkv·webm·3gp, 아이폰 HDR·세로 영상 가능, 파일당 2GB까지 |
| 전달 | 메신저 전송은 소리까지 압축될 수 있음 → 파일 복사·클라우드 |
| 보관 | `data/raw/사람이름/` — **Git에 올리지 않음** (`.gitignore`) |
| 동의 | 영상에 나온 사람에게 연구용 사용 동의 |

말 없는 풍경 영상은 T4(B롤) 시험용으로 따로 분류한다.

| 항목 | 내용 |

| 학습 데이터 | AI Hub 「대화형 음성인식용 자유발화」(KsponSpeech, 간투사 전사 포함으로 소개됨 — **이용 약관·재배포 조건 확인 필요**) + NG·촬영 지시 합성 데이터 |

| 배포 | ONNX 변환 + 8비트 양자화 → 앱은 `onnxruntime`(CPU)만 추가, 모델이 없으면 규칙으로 대체 |
| 평가 | T1 시험 데이터로 규칙 하이브리드 vs 모델 하이브리드 비교 — 나아지지 않으면 넣지 않는다 |
