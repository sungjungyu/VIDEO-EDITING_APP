# ADR 0001 — 렌더 엔진을 FFmpeg 필터 그래프 하나로

- 상태: 채택 (2026-10-27)
- 결정한 사람: 성준규 (렌더 담당), 검토 필요: 조경우·권용관·신정빈

## 배경

렌더 경로가 둘이었다.

| 경로 | 쓰던 곳 | 문제 |
| --- | --- | --- |
| `main.py` MoviePy + PIL 자막 | main 브랜치 앱 | 프레임마다 Python에서 합성해 느림. 외곽선·배경 상자 설정이 렌더에 반영되지 않음. 한 클립만 |
| `media_engine` concat demuxer + `-c copy` + ASS | yonggwan-test 통합 브랜치 | 컷이 키프레임에 끌려감: 키프레임 5초 간격 영상에서 5초를 남기면 **8.09초**(실측). 시스템 ffprobe 필요(팀 PC에 없음). PlayRes가 없어 자막 크기가 미리보기와 다름 |

자막 타이밍은 '자른 결과 길이'를 기준으로 계산하므로 컷이 몇 초씩 틀리면 자막도 밀린다. 또 두 경로를 함께 고치느라 같은 일을 두 번 하고, 병합할 때마다 충돌했다.

## 결정

`vibecut/render`의 **FFmpeg 필터 그래프 하나**로 통일한다.

- 구간마다 `trim`/`atrim`(재인코딩)으로 프레임 단위 컷. 경계는 planner가 클립 프레임 격자에 맞추고, 영상 trim은 반 프레임 앞당겨 경계 프레임을 확실히 고른다
- 클립 통일(scale+crop, setsar, 48kHz 스테레오) → `concat` → `fps` → `subtitles`(libass) → `format=yuv420p`를 한 번에 → 인코딩 1회
- 자막은 ASS (PlayRes = 출력 해상도, 크기는 글꼴 win 메트릭으로 CSS px와 맞춤, 배경 상자는 BorderStyle 4)
- ffmpeg는 imageio-ffmpeg 내장 바이너리로도 동작 (ffprobe 대신 `ffmpeg -i` 출력 파싱)

PIL 자막(둥근 상자 등)은 쓰지 않는다. ASS로 못 그리는 스타일이 꼭 필요하면 PNG를 만들어 `overlay`로 더하는 방식을 나중에 붙일 수 있다.

## 결과

- 키프레임 5초 간격 영상: 5.00초, 첫 프레임 정확 (tests/test_render_engine.py)
- 해상도·fps가 다른 클립 + 소리 없는 클립 + 컷 27개: 영상·소리 길이 차이 0.05초 이내
- 미리보기와 렌더 자막 영역 차이 0~3px (960x540 기준, 실측)
- 35초 결과를 540p로 약 4초, 1080p medium으로 약 7초에 렌더 (테스트 PC CPU)
- MoviePy 의존성 제거, media_engine·backend 삭제. 이전 작업 트리(MoviePy 개선판)는 `wip/moviepy-render` 브랜치에 보존 — 컷 앞뒤 여유(0.08/0.12초)와 25ms 오디오 페이드, 펀치인 아이디어는 새 엔진으로 옮김
- 단점: 모든 구간을 재인코딩하므로 `-c copy`보다 느리다. 대신 컷이 정확하고, 인코딩은 한 번뿐이다
