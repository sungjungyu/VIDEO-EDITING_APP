# ADR 0003 — 패키지를 계층 구조로 재편하고 중복·불필요한 계산을 줄인다

- 상태: 채택 (2026-10-27)
- 결정한 사람: 성준규, 검토 필요: 조경우·권용관·신정빈
- 이전 결정: [ADR 0002](0002-저장소-구조-정리.md) (저장소 바깥 구조는 그대로 유지)

## 배경

ADR 0002로 저장소 바깥은 정리됐지만, 패키지 안쪽에는 이런 문제가 남아 있었다.

| 문제 | 예 |
| --- | --- |
| Gemini 호출 경로가 셋 | 글 판단(SDK)·장면 분석(SDK 파일 업로드)·받아쓰기(httpx REST)가 키·재시도·오류 분류·사용량 집계를 따로 함. 받아쓰기·장면 분석의 사용량은 작업 기록에 남지 않음 |
| 엔진과 명령줄이 한 파일 | transcriber.py 680줄에 엔진·후처리·무음 분석·결과 검증·보고서·CLI. 앱은 argparse 인자를 흉내 낸 `SimpleNamespace`로 엔진을 부름 |
| 업무 규칙이 HTTP 라우트 안에 | 타임라인 검사·클립 삭제 규칙·AI 가편집 흐름이 라우트에 있고, 명령줄은 같은 흐름을 따로 다시 구현 |
| 의존 방향이 거꾸로 | 컷 판단(ai)이 편집 계획(edit)의 지시어 규칙을, 장면 선택(ai)이 편집 계획·시간 변환을 가져다 씀 |
| 중복 | 영상 확장자 3곳, JSON 캐시 3곳, 재시도 3곳, 단어 잘림 세기 2곳, 자막 기본값 서버·화면 3곳, 진행 맥락 2개(JobContext/CliContext) |
| 불필요한 계산 | 편집할 때마다 analysis.json을 요청 한 번에 2~3번 다시 읽음, 받아쓰기에서 같은 WAV를 2~3번 읽음, 명령줄이 영상 전체를 메모리에 읽어 sha1 계산, 미리보기 자막을 33ms마다 다시 만듦, 검토 목록 600줄을 토글 한 번에 재생성 |

## 결정

**계층**: 위는 아래를 쓰고 아래는 위를 모른다. `tests/test_architecture.py`가 모든 import를 검사한다.

```
5  server · cli                        입구 (HTTP·명령줄) — 얇게
4  services                            사용 사례 + 작업 큐 (API와 CLI가 같은 코드)
3  analysis · editing · render · eval  기능
2  ai                                  Gemini 호출 전부 (ai/client.py)
1  media · storage                     ffmpeg, 디스크
0  domain · errors · settings · log    순수 모델·규칙
```

**최적화**

| 무엇 | 전 | 후 |
| --- | --- | --- |
| 편집 API의 분석 결과 읽기 | 요청마다 2~3번 파싱·검증 | 파일 수정 시각·크기로 캐시 (파일이 바뀌면 자동으로 다시 읽음) |
| 받아쓰기 음량 계산 | 같은 WAV 2~3번 읽기 | 클립당 한 번 재서 분할 지점·무음·말소리 구간이 같이 씀 |
| AI 가편집 장면 길이 계산 | 장면마다 문장 전체 정렬 | 한 번 정렬해 재사용 |
| 명령줄 sha1 | 영상 전체를 메모리에 | 1MB씩 읽기 |
| Gemini 연결 | 클립·요청마다 새로 만듦 | 앱 전체가 하나 공유 |
| 작업 기록 | 끝없이 쌓이고 시작할 때 전부 읽음 | 보관 기간 지난 기록 정리 |
| 미리보기 자막 | 33ms마다 DOM 전부 재생성 | 보이는 자막·카라오케 단어·페이드가 바뀔 때만 |
| 검토 목록 | 토글 한 번에 600줄 재생성 | 바뀐 줄만 교체 |
| 타임라인 끌기 | 마우스 이벤트마다 전체 재생성 | 화면 갱신 주기마다 한 번 |

**새로 집계**: 받아쓰기·장면 분석의 Gemini 사용량도 작업 기록·평가 지표의 AI 사용량에 들어간다.

## 기능을 그대로 지킨 방법

- **골든 회귀 테스트**(`tests/regression/`): 리팩터링 전 코드로 만든 프롬프트 4종·응답 스키마·AI 캐시 키·규칙 판단·트리·편집 계획 4가지·렌더 전 검사·ASS 자막·AI 가편집 결과·OpenAPI 모양을 저장해 두고 비교 → 모두 동일. 프롬프트·스키마가 같아 저장해 둔 AI 응답(오프라인 시연)을 그대로 쓴다
- 실제 `data/` 프로젝트의 편집 계획·검사·평가 지표: 전후 동일
- 화면: 개편 전·후를 같은 데이터로 띄워 14개 상태를 Edge로 같은 순서로 조작해 스크린샷 픽셀 비교 → 동일 (재생 헤드 위치만 재생 시간차로 몇 px)
- 업로드 → 분석 → 검토 → AI 가편집 → 편집본 미리보기 → 렌더 전체 흐름을 Edge로 조작 → 콘솔 오류 없음
- 저장 데이터 모양(필드 이름)·받아쓰기/장면 캐시 파일 이름 규칙·API 23개는 바꾸지 않았다

## 결과

- 테스트 103개 (기존 91개 + 골든 회귀·계층 규칙·캐시·작업 정리 등 12개). 예전 media_engine 형식으로 바꾸던 `to_subtitles`는 쓰는 곳이 없어 테스트 2개와 함께 지웠다
- 바뀐 명령: `vibecut-server` → `vibecut serve`, `vibecut a.mp4` → `vibecut edit a.mp4`, `python -m vibecut.ai.engines.transcriber` → `vibecut transcribe`, `python -m vibecut.eval.metrics` → `vibecut metrics`
- 새 의존성 없음
