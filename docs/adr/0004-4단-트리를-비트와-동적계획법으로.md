# ADR 0004 — 4단 장면 트리를 비트(평평한 편집 단위)와 동적계획법 선택으로 바꾼다

- 상태: 채택 (2026-11-08)
- 결정한 사람: 성준규
- 관련: [v4 설계안](../VIBECUT_v4_설계안.md) T3

## 배경

장면 선택과 AI 가편집은 '장소 → 일 → 상황 → 대사' 4단 트리(`analysis/tree.py`) 위에서 동작했다.

| 문제 | 내용 |
| --- | --- |
| 새 정보가 없음 | 트리는 장면 목록과 문장 목록을 시간으로 묶은 사본이다 |
| 단계가 겹침 | Gemini 장면 정리(`clean_scenes`)가 장소·활동이 같은 연속 장면을 이미 합치므로 '상황' = '일'이 된다 |
| 화면 버그 | 부모가 체크된 상태에서 자식 체크를 풀어도 서버에는 부모가 가고, 다시 그릴 때 자식이 다시 체크됐다 (일·상황·대사 탭에서 빼기가 안 됨) |
| 분량 버그 | 장소·일을 📌 고정하면 그 안의 상황 노드 길이를 한 번 더 세어 결과가 목표보다 크게 짧아졌다 (목표 60초 → 30초) |
| 선택 품질 | 점수 높은 순으로 채우는 greedy라 조합으로 맞출 수 있는 경우를 놓쳤다 (예: 60·50·40초 중 90초 → 60초에서 멈춤) |
| 시간 기준 | 트리만 '원본 초'를 써서 클립 초로 바꾸는 변환이 필요했다 |

## 결정

**비트** (`analysis/beats.py`, `domain/models/analysis.py` `Beat`) — 편집 단위의 평평한 목록, 시각은 클립 초.

- 말 비트: 클립·장면이 바뀌거나 2초 이상 쉬면 나누고, 그 안은 TextTiling 방식 주제 경계(앞뒤 3문장 글자 2개 묶음
  분포의 코사인 유사도 골 깊이 + 쉼 길이)로 나눈다. 30초를 넘으면 반드시, 15초를 넘고 경계가 뚜렷하면 나눈다
  (조각은 6초 이상). id는 첫 문장 id(`b-t0001`)라 다시 분석해도 최대한 유지된다
- B롤 비트: 말 없는 구간(2.5초 이상)에서 고른 2~5초. 고르는 기준은 `pick_window`로 바꿀 수 있다 (T4 품질 곡선)

**선택** (`editing/select.py`) — 0/1 배낭 문제를 0.1초 단위 동적계획법으로 정확히 푼다.

- 가치 = Σ 점수 × 실제로 남는 길이 − 2·평균 점수·|결과 − 목표| (목표에 가깝게, 그 안에서 좋은 비트)
- 제약: 목표 ±5%, 고정·must는 반드시, never는 넣지 않음, B롤은 목표의 25%까지 (모자라면 제한을 풀고 다시)
- 비트를 붙여 고르면 여유·쉼 처리로 합이 조금 달라지므로 실제 길이를 다시 재고 벗어나면 목표를 보정해 한 번 더 푼다
- 같은 내용을 다시 말한 비트(유사도 ≥ 0.6)는 점수가 낮은 쪽을 깎는다

**그 밖에**

- `Selection.node_ids`·`ai_node_ids` → `beat_ids`·`ai_beat_ids`, API `/select`의 `node_ids` → `beat_ids`
- 장소 이름 자막은 트리 대신 장면 분석의 장소 이름으로, 결과 영상에서 장소가 바뀌는 곳에 띄운다
- ③ 분량·장면 화면은 탭 없는 시간순 목록 하나, 장소가 바뀌는 곳에만 구분선 (체크 · 📌 · 이유 · 길이)
- `analysis/tree.py`, `TreeNode`, `flatten_tree`, `global_to_clip`, 화면의 `globalToClip`을 지운다

## 확인한 것

- 장면을 고르지 않은 편집 계획(전체·문장 수정·제목/장소 자막·9:16)은 골든 스냅샷에서 남는 구간·자막·장소 자막이
  그대로다 (바뀐 것은 선택 필드 이름뿐). 컷 판단·수정 요청·장면 분석 프롬프트도 그대로
- 회귀 입력(클립 2개, 64초)에서 목표 15·20·25·30·35초가 모두 ±5% 안 (예전 greedy: 목표 35초 → 28.8초도 나옴),
  재료가 모자란 45초는 경고
- 단위 테스트: greedy가 놓치는 조합(60·50·40초 → 90초), 고정·never·시간순, B롤 제한과 해제, 주제 경계, 길이 제한

## 결과

- 다시 분석하면 비트 id가 바뀐 경우 장면 선택을 '전체 사용'으로 되돌린다 (예전 트리와 같은 규칙)
- 예전에 저장한 계획의 `node_ids`는 읽지 않는다 (프로젝트는 서버를 켜고 끌 때 지워지므로 영향 없음)
