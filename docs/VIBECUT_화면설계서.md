# VIBE CUT 화면 설계서 (프론트엔드 리뉴얼)

팀 FRIDAY · 캡스톤디자인2 · 작성 2026-11-01 · 작성 조경우
상태: 초안. API 경로와 JSON 필드는 백엔드(권용관)와 합의한 뒤 확정한다.

> 프론트 스택: **React + Vite** (`frontend/` 폴더). 개발 중에는 Vite 개발 서버에서 `/api`를 FastAPI로 프록시하고, 배포·시연 때는 `npm run build` 결과(`frontend/dist`)를 FastAPI가 정적 파일로 띄운다. 기존 `static/index.html`, `static/editor.html`은 새 화면이 완성되면 삭제한다.
>
> 색·글꼴: 모든 색과 간격은 `src/styles/tokens.css`의 CSS 변수(예: `--color-bg`, `--color-surface`, `--color-accent`, `--color-success`, `--color-warning`, `--color-danger`, `--color-text`, `--color-text-muted`, `--radius`)로만 쓴다. 컴포넌트 안에 색 값을 직접 쓰지 않는다. 팔레트는 나중에 이 파일만 바꿔서 통일한다.
>
> 목업: `docs/mockups/`의 HTML은 레이아웃·비율·상태 표시 참고용이다. 인라인 스타일과 하드코딩된 값을 복사하지 말고, 컴포넌트와 스타일은 새로 구성하며, 데이터는 `mock/`의 JSON에서 읽는다.

## 0. 설계 원칙

1. **흐름형 화면**: 캡컷 같은 자유 편집기가 아니라, 한 단계씩 진행하는 흐름이다. 각 단계는 하나의 일만 한다.
2. **보는 사람은 심사위원**: 고객용 꾸밈보다 **AI가 안에서 무엇을 했는지**가 보여야 한다. 단, 기본 화면은 단순하게 두고 자세한 내용은 "자세히 보기"로 펼친다.
3. **사실만 표시**: 실제로 계산하거나 실행한 것만 화면에 띄운다. 구현되지 않은 검수 항목, 알 수 없는 진행 위치(예: Gemini가 지금 몇 초를 보는지)는 표시하지 않는다.
4. **AI가 판단하고 코드가 실행한다**: LLM은 ID를 고르고, 시각 계산·컷·렌더는 코드가 한다. 화면도 이 구분을 드러낸다(꼭 지킬 것 = 코드, 참고할 것 = AI).
5. **미리보기 = 렌더**: 자막 미리보기와 실제 렌더 결과가 같아야 한다(같은 폰트 파일, 같은 값).

## 1. 전체 흐름

```
① 가져오기 → ② 요청 → [확인 창] → ③ 분석 중 → ④ 구조 편집 → ⑤ 편집 중 → ⑤ 결과 확인 → 내보내기
                 ↑__________|                     ↑___________________________|
             (다시 쓰기)                        (구조 편집으로 돌아가기 / 렌더 취소)
```

| # | 화면 | 하는 일 | 다음으로 가는 조건 |
| --- | --- | --- | --- |
| S1 | 가져오기 | 클립 업로드, 순서 정하기 | 클립 1개 이상 |
| S2 | 요청 | 목표 분량, 한 줄 설명, 편집 의도, 스타일 | 목표 분량 + 한 줄 설명 입력 |
| S2-1 | 확인 창 (팝업) | AI가 해석한 판단 규칙 확인·수정 | "확정하고 분석 시작" |
| S3 | 분석 중 | 받아쓰기 + 영상 이해 + 맞추기 + 4단 구조화 진행 표시 | 모든 단계 완료 |
| S4 | 구조 편집 | 4단 트리에서 켜기/끄기, AI 자동 압축 | "렌더" |
| S5 | 편집 중 | 렌더 진행 표시 | 렌더 완료 |
| S5-1 | 결과 확인 | 미리보기, 요약, 돌아가기/내보내기 | — |

### 프로젝트 상태값

`created → clips_ready → request_confirmed → analyzing → analyzed → rendering → rendered`
(실패 시 `analyze_failed`, `render_failed`. 렌더 취소 시 `analyzed`로 복귀)

새로고침해도 상태값으로 해당 화면을 복원한다. 작업 상태는 서버 메모리가 아니라 **SQLite에 저장**한다("창을 닫아도 분석은 계속돼요" 문구의 전제).

## 2. 공통 레이아웃

- **상단 바**: 왼쪽 로고(V) + 단계 표시 `① 가져오기 ─ ② 요청 ─ ③ 분석 ─ ④ 구조 편집 ─ ⑤ 결과`. 끝난 단계는 ✔, 현재 단계는 굵게. 오른쪽은 화면별 상태(클립 수·총 길이, 경과 시간 등).
- **하단 바**: 왼쪽 "← 이전", 오른쪽 주요 버튼(다음). 조건이 안 맞으면 비활성.
- 진행 중 화면(S3, S5)은 같은 틀을 쓴다: 제목 → 단계 칩 → 가운데 그림 → 진행 막대 → "자세히 보기"(접힘) → 하단 버튼.

## 3. 화면별 명세

### S1. 가져오기

**레이아웃**: 2열 카드 그리드.

- 카드: 썸네일, 번호 배지(①②…), 파일명, 길이, 촬영 시각, 해상도·비율, × 삭제
- 마지막 칸: "+ 영상 추가" 카드(클릭·드래그 앤 드롭)
- 카드 드래그로 순서 변경 → **이 순서가 곧 타임라인 순서**
- "촬영 시각순 정렬" 버튼 (메타데이터 기준)
- 하단 요약 줄: `클립 5개 · 총 60:00 · 비율 16:9 ×4, 9:16 ×1` + "다음"

**출력**: `clips` (§4.1)

### S2. 요청

**레이아웃**: 왼쪽 52% 기획 / 오른쪽 48% 스타일.

왼쪽 (기획, AI 판단의 기준)
- 목표 분량 (분·초) — 필수
- 영상 한 줄 설명 — 필수. 예: "친구랑 편의점 갔다가 집에서 먹방하는 밤 브이로그"
- 편집 의도 (자유 입력, 선택) — 힌트: 강조할 장면, 줄일 장면, 꼭 넣을·뺄 장면, 등장인물
- 안내: "다음을 누르면 AI가 이해한 내용을 항목으로 보여드려요"
- 영상 목적은 선택지로 받지 않는다. AI가 한 줄 설명과 의도에서 추론해 확인 창에 보여준다.

오른쪽 (스타일, 코드가 그대로 실행)
- 프리셋: 기본 / 강조 / 깔끔 (시작값만 채움)
- 화면 비율: 16:9 / 9:16 / 1:1, 비율 다른 클립: 가운데 자르기 / 여백 채우기
- 자막 미리보기(선택한 비율 모양, 설정 즉시 반영)
- 자막: 켜기, "등장인물 말만"(켜기만 여기서. **누구 말인지는 S4에서 선택**, 화자 분리 후에 알 수 있으므로)
- 글꼴(서버에 포함된 한글 폰트 목록) + 크기(pt), 색(#RRGGBB), 외곽선(켜기·두께·색), 배경 박스, 위치(아래/위)
- 인트로 / 아웃트로 영상 업로드(선택)
- "이 스타일을 내 프로필로 저장" 체크

**출력**: `request_input` → 서버가 해석 → S2-1. 스타일은 `execution_rules` (§4.3)

### S2-1. 확인 창 "이렇게 이해했어요" (팝업)

S2 위에 모달로 뜬다(배경 흐림).

- 영상 성격: AI 추론값 칩(✎ 수정)
- 목표 분량 표시
- **꼭 지킬 것** 박스, 배지 "코드가 반드시 지킴": 꼭 넣기 / 꼭 빼기 칩 (× 삭제, + 추가)
- **참고할 것** 박스, 배지 "AI가 고를 때 참고": 강조 / 줄일 것 칩
- 등장인물: "빨간 후드 = 민수" 같은 칩
- **⚠ 확인이 필요해요 (n)**: 서버가 준 `ambiguities` 목록. 항목마다 선택지 버튼
  - 예1: "한강 도착"이 한 줄 설명에 없음 → [그대로 두기] [꼭 넣기에서 빼기]
  - 예2: "먹방 위주" 비율 → [30%] [50%] [70%] [AI에게 맡기기]
  - 이 경고는 영상 보기 전 **텍스트끼리 비교**한 결과임. 실제 존재 여부는 S4에서 다시 확인(§3 S4 참고)
- "AI가 만든 판단 규칙 보기 (JSON)" 접힘 영역
- 하단: [← 프롬프트 다시 쓰기] [확정하고 분석 시작 →]

**동작**
- 칩 수정·삭제·추가는 **JSON을 직접 수정**한다(LLM 재호출 없음).
- LLM 재호출은 "프롬프트 다시 쓰기"로 S2에 돌아가 다시 "다음"을 누를 때만.
- 확정 시 `judgment_rules` 저장 + 분석 시작 요청.

### S3. 분석 중

- 제목 "③ 분석 중…"
- 단계 칩: `1. 받아쓰기` `2. 영상 분석 · 클립 4/5` `3. 말·장면 맞추기` `4. 4단 구조화` (완료 ✔ / 진행 강조 / 대기). 1·2는 동시에 진행되므로 칩을 돌려 보여주지 않고 나란히 둔다.
- 가운데 그림: **분석 중인 클립의 저해상도 캐시 프레임을 2~3초마다 넘기는 슬라이드**. 문구는 "분석 중인 클립: 집_먹방". "AI가 지금 보는 장면"이라고 쓰지 않는다(요청 1회에 클립 전체를 처리하므로 위치를 알 수 없음).
- 진행 막대 + %, 예상 남은 시간, "창을 닫아도 분석은 계속돼요"
- 자세히 보기(접힘)
  - 클립별 표: 받아쓰기·영상 분석 상태(완료/진행 %/대기/실패 + [다시 시도])
  - AI가 발견한 것 로그: `[장면 경계] 편의점 → 계산대`, `[합침] 8초 장면을 다음 장면에 붙임`, `[인물] 빨간 후드 = 민수` 등. **scene_analyzer의 실제 처리 기록만** 출력. 클립(또는 조각) 단위로 몰아서 갱신
  - 숫자 요약: 전체 길이, 장면 수, 문장 수, 화자 수, API 비용(usage 토큰으로 계산)
- 하단: [구조 편집 시작 →] 완료 전 비활성

**진행률 계산**
- `percent = Σ 단계비중 × (끝난 클립 길이 / 전체 길이)`; 비중 받아쓰기 30, 영상 분석 50, 맞추기·구조화 20
- 요청 1회 안에서는 진행 정보가 없으므로 긴 클립은 `--chunk-min 10`으로 잘라 10분 단위로 막대가 움직이게 한다.
- 클립 하나가 실패해도 나머지는 계속. 실패 클립만 재시도.

### S4. 구조 편집

**레이아웃**: 위 70~80% = 왼쪽 60% 트리 + 오른쪽 40% 상세, 아래 20~30% = 타임라인.

트리 (밀러 컬럼 4열): `장소·사건 | 일 | 상황 | 장면`
- 왼쪽 열에서 고르면 오른쪽 열에 하위 항목이 나온다(macOS Finder 열 보기 방식).
- 각 항목: 제목, 길이, 상태 표시
- 상태: 켜짐 / 꺼짐(음영) / 일부 켜짐(빗금) / AI가 고름(별도 표시) / 꼭 넣기·꼭 빼기(아이콘)
- 조작: **Space = 켜기/끄기**, 방향키 이동, 우클릭 메뉴 [꼭 넣기] [꼭 빼기] [잠금 해제]
- 상위 항목을 끄면 하위 전체가 꺼지고, 하위 일부만 켜져 있으면 상위는 "일부 켜짐"

상세 (선택한 항목)
- 해당 구간 영상 재생(저해상도 프록시)
- 장면 정보: 원본 클립·시각, 장소, 활동, 인물
- 받아쓰기 문장 목록(화자, 시각). 문장 클릭 시 그 위치 재생
- AI 선택 이유(자동 압축 후)
- 상단 작은 설정 버튼: **자막 대상 화자 선택**(화자 분리 결과로 목록 생성, S2의 "등장인물 말만"이 켜져 있을 때)

타임라인 (아래)
- 전체 원본 길이 기준 막대. 켜진 구간은 장소·사건별 색, 꺼진 구간은 회색
- 지금 선택한 항목은 테두리로 강조, 확대해서 보여줌
- 표시: `선택 합계 10:04 / 목표 10:00`, 현재 경로(편의점 > 과자 고르기 > …)

버튼
- **[AI로 목표 분량 채우기]**: 꼭 넣기·꼭 빼기를 먼저 고정 → 남은 시간 안에서 AI가 참고할 것을 반영해 선택 → 결과를 "AI가 고름" 상태로 트리에 표시. 사용자가 다시 수정 가능
- **[렌더 →]**
- 꼭 넣기 대상을 트리에서 찾지 못했으면 경고 띄움(S2-1 경고의 실제 검증)

### S5. 편집 중

- 제목 "⑤ 편집 중…"
- 단계 칩: `1. 편집 지시서` `2. 렌더 전 검수` `3. 자르기·이어붙이기 · 14/23` `4. 자막 입히기` `5. 인트로·아웃트로` (렌더 구조에 맞춰 성준규와 확정. 자막을 ASS 한 번으로 입히면 3·4가 합쳐질 수 있음)
- 가운데: **결과 영상 타임라인이 구간별로 채워지는 막대**(장소·사건 색), 지금 처리 중 구간 깜빡임, `지금: 과자 언박싱 (집_먹방 12:30~13:41)`
- 진행 막대: FFmpeg `-progress pipe:1`의 `out_time`으로 **실제 진행률** 계산
- 자세히 보기(접힘)
  - 렌더 전 검수: 단어 경계 보정, 오디오 페이드, 지시 발언 제외, 꼭 넣기/빼기 통과. **구현된 검사만 표시**
  - 적용 설정: 비율·자르기 방식, 자막 스타일, 자막 대상 화자, 인트로/아웃트로
- 하단: [취소하고 구조 편집으로] (선택 상태 유지) / [결과 보기 →] 완료 전 비활성

### S5-1. 결과 확인

편집 불가. 확인 → 돌아가기 또는 내보내기만.

**레이아웃**: 왼쪽 58% 미리보기 / 오른쪽 42% 요약.

왼쪽
- 결과 영상 플레이어(선택한 비율 모양)
- 구간 타임라인(구간 n개, 장소·사건 색, 재생 위치 선). 구간 클릭 시 그 위치로 이동
- 선택한 구간 카드: 이름, 원본 위치, **AI가 남긴 이유**

오른쪽
- 결과 요약: 원본 길이, 결과 길이, 목표 대비 ±초
- 장소·사건별 비율 막대
- 요청 반영: 꼭 넣기 포함 여부(코드 검사), 줄일 것 전후 길이, 검수 보정 수
- 작업 시간: 분석 + 구조 편집(S4 진입 → 렌더 클릭) + 렌더 = 합계 → 평가에서 수동 편집 시간과 비교

하단
- [← 구조 편집으로 돌아가기]: 선택 상태 그대로 S4로
- [스타일만 바꾸기]: S2 오른쪽 스타일 패널만 팝업으로 열고, 다시 렌더(분석·선택 유지)
- [내보내기 ↓]: MP4, 자막 SRT, 편집 지시서 JSON(평가·디버깅용, 시연에서는 숨길 수 있음)

### 4.4 4단 트리 tree (S3 결과, S4 입력)

기존 `prompt_builder.py`의 **트리 계약**(재귀 구조 `id / title / start / end / children`, 선택 항목 `summary`, `tags`)을 그대로 따르고 필드만 추가한다. 그래야 `scene_selector.py`(자동 선택)와 `validate_response`(분량·포함·제외 검증)를 그대로 쓸 수 있다.

```json
{
  "tree": [
    { "id": "t1", "level": "topic", "title": "편의점", "start": 0.0, "end": 760.0, "summary": "...",
      "children": [
        { "id": "k1", "level": "task", "title": "과자 고르기", "start": 252.0, "end": 650.0,
          "children": [
            { "id": "s1", "level": "situation", "title": "어떤 과자 살지 고민", "start": 300.0, "end": 410.0,
              "children": [
                { "id": "sc1", "level": "scene", "title": "칼로리 확인", "start": 352.0, "end": 371.0,
                  "clip_id": "c2", "place": "편의점", "activity": "과자 고르기", "people": ["민수", "경우"],
                  "sentence_ids": ["l88", "l89"], "children": [] }
              ] }
          ] }
      ] }
  ],
  "sentences": [
    { "id": "l88", "speaker": "S1", "text": "칼로리 보소", "start": 355.2, "end": 356.4 }
  ],
  "speakers": [{ "id": "S1", "name": "민수" }, { "id": "S2", "name": "경우" }]
}
```

- 추가 필드: `level`(topic | task | situation | scene), 장면 노드의 `clip_id`, `place`, `activity`, `people`, `sentence_ids`. 최상위에 `sentences`, `speakers`
- **필수 수정**: 현재 `_normalize_node()`는 id·title·start·end·children·summary·tags만 새 dict에 담아서 **추가 필드를 버린다**. 알 수 없는 필드는 그대로 복사하도록 고친다.
- 장면 노드는 `scene_analyzer.py` 출력(scenes.json)에서 만든다. `sentences`, `speakers`는 받아쓰기와 맞추는 1-3 작업 전까지 mock으로 채운다.
- 4단계(장소·사건 → 일 → 상황 → 장면)를 묶는 로직(1-3)은 아직 저장소에 없다. 확정되면 이 절을 갱신한다.

### 4.5 선택 상태 selection (S4)

```json
{
  "target_sec": 600,
  "nodes": {
    "sc1": { "state": "on", "by": "ai", "reason": "요청의 '과자 고르기' 강조", "lock": null },
    "sc7": { "state": "on", "by": "user", "lock": "must_include" },
    "sc9": { "state": "off", "by": "user", "lock": "must_exclude" }
  },
  "total_sec": 604
}
```
- 저장은 **장면(leaf) 단위만**. 상위 노드의 켜짐/일부/꺼짐은 화면에서 계산
- `by`: user | ai, `lock`: must_include | must_exclude | null

### 4.6 편집 지시서 edl (S5 입력)

```json
{
  "segments": [
    { "order": 1, "scene_id": "sc1", "clip_id": "c2", "src_start": 100.0, "src_end": 119.0,
      "global_start": 352.0, "global_end": 371.0, "fade_in": 0.05, "fade_out": 0.05 }

```
`src_*`는 원본 클립 내부 시각(렌더용), `subtitles` 시각은 결과 영상 기준(코드가 재계산).

## 6. 구현 순서

0. `frontend/`에 React + Vite 프로젝트 생성, `tokens.css`, Vite `/api` 프록시 설정
1. **가짜 데이터로 화면 먼저**: §4의 JSON 예시를 `mock/` 폴더에 두고 S1 → S5-1까지 클릭으로 끝까지 넘어가게 만든다(백엔드 없이)
2. 상태값 라우팅 + 새로고침 복원
3. S4 구조 편집(가장 큼): 밀러 컬럼 → Space 토글 → 타임라인 → 우클릭 잠금 → 상위 상태 계산
4. progress 폴링 연결(S3, S5), 실제 API로 하나씩 교체
5. S2 자막 미리보기 = 렌더 일치 확인(성준규와 같은 폰트 파일 사용)

## 7. 이번 범위에서 하지 않는 것

- 자유 편집기(구간 길이 직접 끌기, 트랙 여러 개, 효과)
- 결과 화면에서 편집
- 카라오케 자막, 템플릿, 필터, 실행취소/다시실행
- 로그인·계정(프로필은 로컬 저장)
